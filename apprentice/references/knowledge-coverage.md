# 知识完整性与缺口管理（防乱答 · 主动补缺 · 能力边界自知）

> 回答四个问题：行业知识以什么形式存在？如何保证搜到的知识完整？有缺失时如何不乱答？如何主动找到缺失部分？
> 原理：**会做已搜到的题 ≠ 获得行业能力**。行业能力 = 任务空间（类型×难度）上的覆盖面 + 对未覆盖区的自知。本文件是 skill 的贯穿机制层，作用于全部四阶段。

## 一、行业知识的七种存在形式

| # | 形态 | 载体 | 性质 | 可信度 |
|---|---|---|---|---|
| 1 | 程序性知识（怎么做） | SOP / 工作流文档（v1→v2→v2.1） | 显性 | 高（经审核） |
| 2 | 判别性知识（凭什么下结论） | 方法论体系 / 证据权重表 | 显性 | 高（译自行业共识） |
| 3 | 事实性知识（原材料） | 结构化语料库（db / 索引 / 图片） | 显性 | 高（原始材料） |
| 4 | 案例性知识（这一题怎么解的） | 单案研究档案 | 显性 | 中–高 |
| 5 | 失败性知识（什么会错） | 红线 / 错题本 / 已排除假设 | 显性 | 高 |
| 6 | 元知识（进展 / 缺口 / 教训） | 总进度 / 缺口登记簿 / 能力画像 | 显性 | 高 |
| 7 | 领域通识（背景直觉） | **模型权重** | **隐性** | **不可证 ← 乱答之源** |

**核心论断：乱答只来自第 7 种。** 前六行都可审计、可召回、可被下一个会话继承；模型权重里的"行业知识"在任务压力下会伪装成结论输出。对策不是"让模型不乱答"（做不到），而是**逼它对每条论断声明来自哪一行**——即三级来源标注（见第五节）。

知识外化的两条路线，必须双轨并行：
- **需求驱动**（现状）：任务用到什么才外化什么——效率高，但有盲区；
- **供应驱动**（本文件新增）：对照领域权威普查工件主动盘点——保证覆盖面。

## 二、供应侧完整性：领域知识总账 + 权威普查工件对照

**绝对完整不可保证，可操作的是"相对权威普查工件的覆盖率"。** 每个领域都存在"普查工件"（census artifacts）——行业自己编制的完整性清单：

| 普查工件 | 通用形态 | 甲骨文领域实例 |
|---|---|---|
| 教材目录 / 经典书章节结构 | 学科知识地图 | 《甲骨文字释林》篇目 |
| 认证考纲 / 资格标准 | 从业能力清单 | 文字博物馆悬赏论证格式 |
| 分类法 / 编目 / 总录 | 对象全集清单 | 《新甲骨文编》收字总表、《合集》著录号 |
| 数据集类目 | 已标注对象空间 | HUST-OBC 8,292 类（含未释 9,408 码位） |
| 招聘 JD 聚类 | 行业任务清单（免费的） | —— |
| 社区高频求助帖 / FAQ | 行业难点清单 | 殷契文渊论坛、学界争论点 |
| 章末习题 / 历年真题分布 | 考点清单 | 考释学界经典问题集 |

**操作**：
1. 阶段一即建 `研究档案/知识总账.md`：左侧列权威普查工件逐项展开的知识区（例如按字编部首 / 按考纲章节 / 按 JD 任务项），右侧三态标记：〔已覆盖·有档案〕〔部分覆盖〕〔未覆盖〕；
2. 计算**覆盖率**＝已覆盖区 / 总区数——这是"前期搜到的行业知识完整度"的唯一可操作度量；
3. **三源交叉验证**：≥3 个独立权威源；**两源分歧本身就是缺口信号**（记录为缺口，不是随手二选一）；
4. 覆盖率不要求 100%，但**必须知道自己是多少**，且未覆盖区在第 5、6 节机制下被显式声明。

## 三、任务空间地图与能力画像（真实任务处理与判别能力的度量）

**"真正获取了行业知识"无法直接验证，只能验证"在分层抽测任务上的迁移表现"。** 三步：

1. **任务空间地图**（阶段一建，随认知升级）：把领域任务拆成 类型 × 难度 矩阵。
   - 类型轴的通用来源：普查工件（考纲章节 / JD 任务项 / 社区求助主题聚类）；
   - 难度轴通用三档：**已知答案型**（有定论可对拍）／**争议型**（学界或行业内有两说以上）／**开放型**（无共识，如真未释字、开放设计题）。
   - 甲骨文例：异体合并 / 部件类推 / 高频未释 / 孤例残字 ×（定论 / 争议 / 未释）。
2. **分层抽测**（RSI 每轮强制）：按类型配额抽测，**不许只做目标池里最易的**——否则能力画像会被幸存者偏差污染（"只会做一类题"）。
3. **能力画像**（`研究档案/能力画像.md`，滚动更新）：

   | 任务类型 | 难度 | 实测次数 | 通过率 | 证据（验收/审核档案链接） | 状态 |
   |---|---|---|---|---|---|
   | 例：异体合并型 | 已知答案 | 5 | 5/5 | v2-验收 | ✅ 已验证 |
   | 例：争议型判读 | 争议 | 2 | 0/2 | v4 审核 | ⚠️ 失败区 |
   | 例：开放型破译 | 开放 | 0 | — | — | ❓ **未测试＝未知** |

   **铁律：未测试＝未知。** 画像里"未知"和"已验证"同等重要——判别"这类任务我能不能做"本身就是行业能力（元认知），没有画像的 AI 接到超纲任务只会硬答。

## 四、主动补缺：缺口驱动学习循环（Gap-Driven Learning Cycle）

```
① 覆盖巡检 ──→ ② 缺口登记 ──→ ③ 定级排序 ──→ ④ 补缺动作 ──→ ⑤ 缺口区复测
     ↖ ______________________________________________ ↙ 更新总账 / 能力画像 / 登记簿销账
```

1. **巡检（四种缺口信号，定期 + 事件触发）**：
   - 定期：每 N 轮 RSI 重跑权威清单 diff（覆盖率复查）；
   - 事件：任务失败（审核不通过）→ 登记为覆盖债，不许只修个案；
   - 事件：权威源之间分歧 → 分歧点即缺口；
   - 事件：专家 / 社区指出盲区（未知未知的唯一可靠探测器——对外暴露面越大约束越强）。
2. **登记**（`研究档案/缺口登记簿.md`）：每条缺口记录五元组——**缺什么 / 怎么知道缺的（信号源）/ 怎么补（动作映射）/ 成本估计 / 阻塞了哪些任务类型**。
3. **定级**：阻塞度（挡住多少任务类型）× 出现频率排序，先补高阻塞。
4. **补缺动作映射**（缺什么→去哪找，通用五招）：

   | 缺口类型 | 标准动作 |
   |---|---|
   | 事实缺失 | 查权威源 / 找新数据集入库 |
   | 方法缺失 | 文献调研该方法的标杆案例，翻译进 SOP |
   | 判据缺失（不知道对错标准） | 找行业共识对拍物（定论集 / 标准 / 专家） |
   | 经验缺失（没做过这类题） | 在缺口区自生成测试题 → 作答 → 对答案 |
   | 暂不可补（外部依赖） | 标〔存而不论〕入登记簿，明示阻塞后果 |

5. **复测**：补缺后在缺口区**自生成考题验证**（self-examination：没学过的章节，主动做章末习题），通过才允许销账并更新能力画像。
   - 甲骨文原型：第六轮"差距清单"（释文逐字核对 / EVOBC 演变链 / 上古音 / 专家推荐）就是缺口登记簿的实战形态；"H 编号＝合集号"通道是任务中偶然发现的供应缺口——若早有巡检制度，它会更早变成全量能力。

## 五、防乱答协议（有缺失时怎么办）

**三级来源标注**——所有输出论断强制标注，审核按标注查证：

| 标注 | 含义 | 使用规则 |
|---|---|---|
| 〔已验证·有出处〕 | 落在语料库 / 档案 / 文献原文 | 可作硬证据 |
| 〔模型记忆·待核对〕 | 来自模型权重（第 7 形态） | 只能作线索；未经核对不得支撑结论（铁律①的具体化） |
| 〔未知·缺口〕 | 总账 / 画像显示未覆盖 | **必须显式声明，禁止用记忆填充冒充知识** |

**强制缺口声明**：正式回答模板必须含两节——"本回答依赖的未验证假设"、"本回答未覆盖的方面"。知识不足时的合法输出只有三种：
1. **降档作答**：只答已验证部分，其余逐条标注（配合置信五档）；
2. **存而不论**：明示"当前知识不足以判断"；
3. **缺口卡**：登记入缺口登记簿，转入第四节补缺循环。
   ——**第四种输出（自信完答）被禁止。**

**答前门控**（接任何任务前 30 秒三问）：
1. 这类任务在能力画像里测过吗？（未测试＝未知 → 至少降档）
2. 答案依赖的知识在总账哪个区、覆盖了吗？（未覆盖 → 触发缺口声明）
3. 哪些论断只是模型记忆？（逐条标"待核对"）

## 六、落地文件模板

> 未启用工具箱时手写以下模板；已启用 `scripts/da_toolbox.py`（见 SKILL.md"配套工具箱"节）时，三件资产由命令维护、`render` 自动生成同构 markdown 视图，禁止手改。

```markdown
# 缺口登记簿（滚动）

```

## 七、与四阶段的关系

- **阶段一**：建知识总账（五件套之一）+ 任务空间地图初版——回答"该知道什么"；
- **阶段二**：盲测 / 验收组的通过率即能力画像首批数据——回答"现在会什么"；
- **阶段三**：独立审核同时是缺口巡检（三类系统病＝三种缺口信号）——回答"哪里虚"；
- **阶段四**：RSI 循环挂上分层抽测 + 定期巡检 + 缺口登记簿燃尽——把"知识完整性"从一次性动作变成持续制度。
